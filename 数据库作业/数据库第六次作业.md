### 1. 简述实现数据库安全性控制的常用技术方法及其内容

实现数据库安全性常用方法有：

1. 用户标识与鉴别：通过用户名口令、生物特征等方式确认身份，防止未授权用户进入系统。
2. 存取控制：用 GRANT/REVOKE 控制用户对表、视图、字段的操作权限，并在执行时做权限检查。
3. 视图机制：给不同用户提供不同数据视图，隐藏敏感行列。
4. 数据加密：对存储和传输数据加密，降低泄露风险。
5. 数据库审计：记录登录、查询、修改等操作，便于追踪和责任认定。
6. 分层安全：数据库安全还需配合操作系统、网络和硬件安全策略。

---

### 2. 什么是数据库中的自主存取控制和强制存取控制？

1. 自主存取控制（DAC）
- 由数据对象拥有者自主授权。
- 特点是灵活、可转授，常用 GRANT/REVOKE 实现。

2. 强制存取控制（MAC）
- 系统按统一密级规则强制控制访问。
- 主体有许可证级别，客体有密级；只有级别匹配才允许读写。

3. 区别
- DAC 侧重灵活管理，MAC 侧重高安全强控制。
- 高安全系统通常同时采用 DAC 和 MAC。

---

### 3. 为什么强制存取控制提供了更高级别的数据库安全性？

因为 MAC 不是由用户自行决定权限，而是由系统按密级统一控制，安全性更高：

1. 权限不能随意转授，减少权限扩散风险。
2. 每次访问都要做“主体级别-客体密级”匹配，越权更难发生。
3. 控制的是带密级标记的数据本身，复制后仍受密级约束。
4. 在实际系统中常与 DAC 叠加使用，形成更完整防护。

### 4. 举例说明如何把视图机制作为一种授权机制使用

思路：先建立视图筛选数据，再在视图上授权。

例：只允许用户“王平”查看 CS 系学生信息。

1. 建立视图

```sql
CREATE VIEW CS_Student AS
SELECT *
FROM Student
WHERE Sdept = 'CS';
```

2. 视图授权

```sql
GRANT SELECT
ON CS_Student
TO 王平;
```

3. 效果
- 王平只能通过视图查询 CS 系数据，不能直接访问基表中的其他数据。
