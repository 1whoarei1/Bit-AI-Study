### 1. DBMS的完整性控制机制应具有哪三方面的功能？

- 定义完整性约束条件的机制。
- 检查完整性约束条件的机制。
- 违约处理机制。

### 2. 请列举可能违反参照完整性的各种情况，以及相应的违约处理策略。

- 对参照表进行插入或修改时，外键值不对应被参照表主键值，应拒绝执行。
- 对被参照表进行删除或修改主键值时，如果参照表中已有相应外键值，常见处理策略有：
  - 拒绝执行（NO ACTION）
  - 级联操作（CASCADE）
  - 置空（SET NULL）

### 3. 考虑如下关系数据库：请使用触发器实现要求

学生表Student(Sno, Sname, Sage, Ssex)

系表Department(Dno, Dname)

学习表Study(Sno, Dno, rank)

要求：在对Student表插入新学生时，也将此学生信息插入到Study表中，不确定的属性置空。

```sql
CREATE TRIGGER Stu_Insert
AFTER INSERT ON Student
FOR EACH ROW
INSERT INTO Study(Sno, Dno, rank)
VALUES (NEW.Sno, NULL, NULL);
```

### 4. 在如下关系数据库中完成各表的定义，并实现约束条件

books(编号，书名，出版社，定价)

readers(编号，姓名，读者类型，已借数量)

borrowinf(图书编号，读者编号，借期，还期)

readertype(类型编号，类型名称)

约束条件：

- borrowinf中“还期”不能小于“借期”。
- readers的列“读者类型”上的默认值为3。
- readers的“已借数量”不小于零。

```sql
CREATE TABLE readertype
(
    typeid   CHAR(10) PRIMARY KEY,
    typename CHAR(20) NOT NULL
);

CREATE TABLE books
(
    bookid   CHAR(10) PRIMARY KEY,
    bookname CHAR(50) NOT NULL,
    press    CHAR(50),
    price    DECIMAL(8,2) CHECK (price >= 0)
);

CREATE TABLE readers
(
    rid     CHAR(10) PRIMARY KEY,
    rname   CHAR(20) NOT NULL,
    rtype   CHAR(10) DEFAULT 3,
    borrown INT CHECK (borrown >= 0),
    FOREIGN KEY (rtype) REFERENCES readertype(typeid)
);

CREATE TABLE borrowinf
(
    bookid  CHAR(10),
    rid     CHAR(10),
    borrowd DATE,
    returnd DATE,
    PRIMARY KEY (bookid, rid, borrowd),
    FOREIGN KEY (bookid) REFERENCES books(bookid),
    FOREIGN KEY (rid) REFERENCES readers(rid),
    CHECK (returnd >= borrowd)
);
```
