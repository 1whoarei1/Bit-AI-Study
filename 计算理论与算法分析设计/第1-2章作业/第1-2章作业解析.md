## 1-1 求下列函数的渐近表达式

求下列函数的渐近表达式（\(\Theta\) 或 \(O\) 表示）：

1. \(3n^2 + 10n\)
2. \(\frac{n^2}{10} + 2n\)
3. \(21 + \frac{1}{n}\)
4. \(\log n^3\)
5. \(10\log n^3\)

### 解答

渐近表达式只保留最高阶项，忽略常数系数。

**（1）\(3n^2 + 10n\)**

最高阶项为 \(n^2\)，故渐近表达式为 \(\Theta(n^2)\)。

**（2）\(\frac{n^2}{10} + 2n\)**

最高阶项为 \(n^2\)，系数 \(\frac{1}{10}\) 被忽略，故渐近表达式为 \(\Theta(n^2)\)。

**（3）\(21 + \frac{1}{n}\)**

当 \(n \to \infty\) 时，\(\frac{1}{n} \to 0\)，因此函数趋近于常数 21。故渐近表达式为 \(\Theta(1)\)。

**（4）\(\log n^3\)**

\(\log n^3 = 3\log n\)，忽略常数系数，故渐近表达式为 \(\Theta(\log n)\)。

**（5）\(10\log^3 n\)**

\(\log^3 n = (\log n)^3\)。最高阶项为 \(\log^3 n\)，忽略常数 10，故渐近表达式为 \(\Theta(\log^3 n)\)。

### 答案汇总

| 函数 | 渐近表达式 |
|------|-----------|
| \(3n^2 + 10n\) | \(\Theta(n^2)\) |
| \(\frac{n^2}{10} + 2n\) | \(\Theta(n^2)\) |
| \(21 + \frac{1}{n}\) | \(\Theta(1)\) |
| \(\log n^3\) | \(\Theta(\log n)\) |
| \(10\log^3 n\) | \(\Theta(\log^3 n)\) |

## 1-2 试论 O(1) 与 O(2) 的区别

### 解答

**O(1) 与 O(2) 没有区别，它们表示同一个渐近上界集合。**

根据大 O 表示法的定义：

\[
f(n) = O(g(n)) \iff \exists c > 0, \exists n_0 > 0, \forall n \ge n_0: f(n) \le c \cdot g(n)
\]

- \(f(n) = O(1)\) 意指存在常数 \(c\) 使得 \(f(n) \le c \cdot 1 = c\)，即 \(f(n)\) 有界。
- \(f(n) = O(2)\) 意指存在常数 \(c\) 使得 \(f(n) \le c \cdot 2 = 2c\)，由于 \(c\) 是任意正常数，\(2c\) 仍为任意正常数，因此 \(f(n)\) 同样有界。

更一般地，对于任意常数 \(k_1, k_2 > 0\)，有 \(O(k_1) = O(k_2) = O(1)\)。因为大 O 表示法中的常数因子会被吸收到不等式系数 \(c\) 中。

**结论**：O(1) 和 O(2) 都表示常数时间复杂度，两者完全等价。在实际算法分析中，我们统一使用 O(1) 表示常数时间。

## 1-4 算法规模与计算机速度的关系

**已知条件**：某算法在输入规模为 \(n\) 时的计算时间为 \(T(n)\)。在计算机 A 上实现并完成该算法的时间为 \(t\) 秒。现有计算机 B，其运行速度是 A 的 64 倍。

### （1）\(T(n) = 3 \times 2^n\)

在计算机 A 上：\(t = 3 \times 2^n\)

在计算机 B 上（速度快 64 倍），同样 \(t\) 秒内能完成的计算量为 A 的 64 倍：

\[
64 \times 3 \times 2^n = 3 \times 2^{n'}
\]

\[
2^{n'} = 64 \times 2^n = 2^6 \times 2^n = 2^{n+6}
\]

\[
n' = n + 6
\]

**答**：在新机器上用 \(t\) 秒时间能解输入规模为 \(n + 6\) 的问题。

**分析**：指数级算法对速度提升不敏感——速度提升 64 倍，问题规模仅增加 6。

---

### （2）\(T(n) = n^2\)

\[
t = n^2
\]

在新机器上：

\[
64 \times n^2 = n'^2
\]

\[
n' = \sqrt{64n^2} = 8n
\]

**答**：在新机器上用 \(t\) 秒时间能解输入规模为 \(8n\) 的问题。

**分析**：多项式算法（平方级）能获得与速度提升平方根成正比的规模增长。

---

### （3）\(T(n) = 8\)

\[
t = 8
\]

\(T(n) = 8\) 为常数时间，运行时间与输入规模无关。在计算机 A 上，任何规模的输入都能在 \(t\) 秒内完成。在计算机 B 上（快 64 倍），同样任何规模的输入都能在 \(t\) 秒内完成（甚至更快）。

**答**：在新机器上用 \(t\) 秒时间能解任意规模的输入。

**分析**：对于常数时间算法，速度提升不改变可处理的问题规模（理论上都是无限）。

---

### 1-4 总结

| 时间复杂度 | 速度提升 64 倍后规模变化 | 增长特性 |
|-----------|------------------------|---------|
| \(T(n) = 3 \times 2^n\) | \(n' = n + 6\) | 指数级：增加常数 |
| \(T(n) = n^2\) | \(n' = 8n\) | 多项式：乘以因子 |
| \(T(n) = 8\) | 任意 | 常数：无限制 |

## 2-8 查找固定点（T[i] = i）

### 问题描述

设 \(n\) 个不同的整数排好序后存于 \(T[1:n]\) 中。若存在一个下标 \(i\)（\(1 \le i \le n\)），使得 \(T[i] = i\)，设计一个有效算法找到这个下标。要求算法在最坏情况下的计算时间为 \(O(\log n)\)。

### 解题思路

由于数组**有序**且元素**互不相同**，可以利用二分查找的思想。

**关键观察**：

- 若 \(T[mid] = mid\)，找到目标，直接返回。
- 若 \(T[mid] > mid\)：由于数组严格递增且元素互异，对于任意 \(j > mid\)：
  \[
  T[j] \ge T[mid] + (j - mid) > mid + (j - mid) = j
  \]
  即 \(T[j] > j\)，右侧不可能存在满足条件的下标。只需在**左半部分**继续查找。
- 若 \(T[mid] < mid\)：对称地，对于任意 \(j < mid\)：
  \[
  T[j] \le T[mid] - (mid - j) < mid - (mid - j) = j
  \]
  即 \(T[j] < j\)，左侧不可能存在满足条件的下标。只需在**右半部分**继续查找。

**举例**：T = [-3, 0, 2, 5, 7]

| 下标 i | 1 | 2 | 3 | 4 | 5 |
|--------|---|---|---|---|---|
| T[i]   | -3| 0 | 2 | 5 | 7 |

- mid = 3, T[3]=2 < 3 → 查找右侧 [4, 5]
- mid = 4, T[4]=5 > 4 → 查找左侧 [4, 3] → 空，不存在

另一个例子：T = [-1, 0, 3, 5, 7]

| 下标 i | 1 | 2 | 3 | 4 | 5 |
|--------|---|---|---|---|---|
| T[i]   | -1| 0 | 3 | 5 | 7 |

- mid = 3, T[3]=3 = 3 → 找到！

### 算法伪代码

```
function findFixedPoint(T[1..n]):
    left = 1, right = n
    while left <= right:
        mid = left + (right - left) / 2
        if T[mid] == mid:
            return mid
        else if T[mid] > mid:
            right = mid - 1
        else:
            left = mid + 1
    return -1  // 不存在
```

### 复杂度分析

- **时间复杂度**：每次将搜索范围减半，\(O(\log n)\)
- **空间复杂度**：\(O(1)\)

### 正确性证明

利用**循环不变量**：如果存在满足条件的下标，它一定在当前的 `[left, right]` 范围内。每次迭代根据 `T[mid]` 和 `mid` 的大小关系安全地排除不可能的一半。当 `left > right` 时，搜索范围为空，确认不存在。

## 2-9 寻找主元素（Majority Element）

### 问题描述

设 \(T[0:n-1]\) 是 \(n\) 个元素的数组。对任一元素 \(x\)，设 \(S(x) = \{ i \mid T[i] = x \}\)。当 \(|S(x)| > n/2\) 时，称 \(x\) 为**主元素**。设计一个**线性时间**算法，确定 \(T[0:n-1]\) 是否有一个主元素。

### 解题思路

使用 **Boyer-Moore 多数投票算法（Boyer-Moore Majority Vote Algorithm）**，分为两个阶段：

#### 第一阶段：找出候选元素

扫描数组，维护 `candidate` 和 `count`：
- 若 `count == 0`，将当前元素设为 `candidate`，`count = 1`
- 若当前元素等于 `candidate`，`count++`
- 若当前元素不等于 `candidate`，`count--`

**直观理解**：将不同的元素两两抵消，如果存在主元素（出现次数 > n/2），它一定会在抵消后"存活"下来。因为主元素的数量超过半数，即使所有其他元素都与它抵消，它仍有剩余。

#### 第二阶段：验证候选元素

遍历数组，统计 `candidate` 出现的实际次数。若 > n/2，则它是主元素；否则，不存在主元素。

**为什么需要验证**：第一阶段只能保证"如果存在主元素，则 candidate 一定是它"，但不能保证 candidate 一定是主元素（比如当不存在主元素时，candidate 可能是任意元素）。

**示例**：T = [2, 2, 1, 3, 2, 2]

| 步骤 | 元素 | candidate | count | 说明 |
|------|------|-----------|-------|------|
| 0 | - | - | 0 | 初始 |
| 1 | 2 | 2 | 1 | count=0，设为候选 |
| 2 | 2 | 2 | 2 | 相同，count++ |
| 3 | 1 | 2 | 1 | 不同，count-- |
| 4 | 3 | 2 | 0 | 不同，count-- |
| 5 | 2 | 2 | 1 | count=0，重新设为候选 |
| 6 | 2 | 2 | 2 | 相同，count++ |

候选为 2，验证：2 出现 4 次 > 6/2 = 3，是主元素。

### 算法伪代码

```py
function findMajority(T[0..n-1]):
    candidate = null, count = 0
    for i = 0 to n-1:
        if count == 0:
            candidate = T[i]
            count = 1
        else if T[i] == candidate:
            count++
        else:
            count--

    occurrences = 0
    for i = 0 to n-1:
        if T[i] == candidate:
            occurrences++
    
    if occurrences > n/2:
        return candidate
    else:
        return null 
```

### 复杂度分析

- **时间复杂度**：两个阶段各遍历一次数组，\(O(n)\)
- **空间复杂度**：\(O(1)\)，仅需两个额外变量

### 正确性证明概要

1. **若主元素存在，第一阶段必返回它**：
   - 将数组元素配对抵消（不同元素互相抵消）。主元素出现次数 > n/2，所以不可能被完全抵消。
   - 在 count 归零时，已扫描部分中，candidate 的出现次数恰好等于非 candidate 的出现次数。剩余部分的全局主元素仍是原数组的全局主元素（因为主元素优势在整个数组中保持）。

2. **第二阶段确认**：
   - 第一阶段的 candidate 是必要条件（如果存在主元素则一定是它），第二阶段统计出现次数验证充分条件。
