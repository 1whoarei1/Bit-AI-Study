 线性时间选择算法分组大小分析

在线性时间选择算法（Median of Medians）中，若将输入元素每 5 个划分为一组，可以保证最坏情况下的线性时间复杂度。下面分析若改为每 7 个一组或每 3 个一组时，算法是否仍为线性时间。

## 一、原算法：5 个一组

设输入规模为 `n`。将元素每 5 个分成一组，则共有约 `n/5` 组。先求出每组的中位数，再递归地求这些中位数的中位数，作为划分主元。

每组 5 个元素的中位数是该组第 3 小的元素。由于所选主元是所有组中位数的中位数，因此至少有一半的组中位数不小于该主元。在这些组中，每组至少有 3 个元素不小于该组中位数，从而也不小于主元。

因此，至少有

```text
(n/5) * (1/2) * 3 = 3n/10
```

个元素不小于主元。同理，至少有 `3n/10` 个元素不大于主元。

所以划分后，最坏情况下递归处理的子问题规模不超过

```text
n - 3n/10 = 7n/10
```

于是递推式为

```text
T(n) <= T(n/5) + T(7n/10) + O(n)
```

其中 `T(n/5)` 是递归寻找中位数的中位数的时间，`T(7n/10)` 是划分后继续递归选择的时间，`O(n)` 是分组、求组内中位数和划分数组的线性时间。

因为

```text
1/5 + 7/10 = 9/10 < 1
```

所以该递推式的解为

```text
T(n) = O(n)
```

因此，5 个一组时算法是线性时间算法。

## 二、改为 7 个一组

若每 7 个元素分成一组，则共有约 `n/7` 组。每组的中位数是该组第 4 小的元素。

同样地，主元是所有组中位数的中位数，因此至少有一半的组中位数不小于主元。在每个这样的 7 元素组中，至少有 4 个元素不小于该组中位数，从而也不小于主元。

因此，至少有

```text
(n/7) * (1/2) * 4 = 2n/7
```

个元素不小于主元。同理，至少有 `2n/7` 个元素不大于主元。

所以划分后，最坏情况下递归处理的子问题规模不超过

```text
n - 2n/7 = 5n/7
```

于是递推式为

```text
T(n) <= T(n/7) + T(5n/7) + O(n)
```

因为

```text
1/7 + 5/7 = 6/7 < 1
```

所以该递推式的解仍为

```text
T(n) = O(n)
```

因此，**若划分为 7 个一组，算法仍然是线性时间算法**。

## 三、改为 3 个一组

若每 3 个元素分成一组，则共有约 `n/3` 组。每组的中位数是该组第 2 小的元素。

主元仍然是所有组中位数的中位数，因此至少有一半的组中位数不小于主元。在每个这样的 3 元素组中，至少有 2 个元素不小于该组中位数，从而也不小于主元。

因此，至少有

```text
(n/3) * (1/2) * 2 = n/3
```

个元素不小于主元。同理，至少有 `n/3` 个元素不大于主元。

所以划分后，最坏情况下递归处理的子问题规模不超过

```text
n - n/3 = 2n/3
```

于是递推式为

```text
T(n) <= T(n/3) + T(2n/3) + O(n)
```

此时

```text
1/3 + 2/3 = 1
```

递归子问题规模之和没有严格小于 `n`。该递推式的解为

```text
T(n) = O(n log n)
```

因此，**若划分为 3 个一组，算法不能保证最坏情况下的线性时间复杂度**。

## 四、结论

| 分组大小 | 递推式 | 时间复杂度 | 是否保证线性时间 |
|---|---|---|---|
| 5 个一组 | `T(n) <= T(n/5) + T(7n/10) + O(n)` | `O(n)` | 是 |
| 7 个一组 | `T(n) <= T(n/7) + T(5n/7) + O(n)` | `O(n)` | 是 |
| 3 个一组 | `T(n) <= T(n/3) + T(2n/3) + O(n)` | `O(n log n)` | 否 |

综上，将元素划分为 7 个一组时，线性时间选择算法仍然保持最坏情况下的线性时间复杂度；而划分为 3 个一组时，算法不能保证线性时间，最坏情况下通常为 `O(n log n)`。
