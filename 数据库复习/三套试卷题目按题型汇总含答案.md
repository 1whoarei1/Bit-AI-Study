## 一、填空题汇总

### 【2011 图片卷】填空题

1. 一般来说，数据模型包括三个方面，分别是 ____ ____、____ ____ 和数据完整性约束。  
   答案：<span style="color:red">数据结构；数据操作</span>

2. 数据库的数据独立性表现在两个方面，分别是 ____ ____ 和 ____ ____。  
   答案：<span style="color:red">物理独立性；逻辑独立性</span>

3. 在关系数据库中，当数据更新操作出现破坏参照完整性而使数据不一致时，系统可采用的策略有 ____ ____、____ ____ 和置空值。  
   答案：<span style="color:red">拒绝执行；级联操作</span>

4. E-R 模型的主要概念是：实体、____ ____ 和 ____ ____。  
   答案：<span style="color:red">属性；联系</span>

5. 嵌入式 SQL 引入 ____ ____ 机制来协调面向集合和面向记录的不同处理方式。  
   答案：<span style="color:red">游标</span>

6. 在关系数据库的查询优化中，可以把某些选择操作同它前面要执行的笛卡尔积结合起来，合并成为一个 ____ ____ 操作。  
   答案：<span style="color:red">连接</span>

7. 在强制存取控制中，仅当主体的许可证级别 ____ ____ 客体的密级时，该主体才能读相应的客体。  
   答案：<span style="color:red">不低于 / 大于等于</span>

8. ____ ____ 是数据库并发控制和恢复的基本单位。  
   答案：<span style="color:red">事务</span>

9. 为了提高多粒度封锁的检查效率，在多粒度封锁机制中引入了 ____ ____ 锁。  
   答案：<span style="color:red">意向</span>

10. 数据库系统的三级模式结构分别是：____ ____、____ ____ 和 ____ ____。  
    答案：<span style="color:red">外模式；模式；内模式</span>

11. 恢复系统故障的方法是对于未完成的事务执行 ____ ____ 操作，对于已完成的事务执行 ____ ____ 操作。  
    答案：<span style="color:red">UNDO / 撤销；REDO / 重做</span>

12. 数据库系统遇到死锁时必须从死锁状态中恢复。解除死锁的方法是 ____ ____。  
    答案：<span style="color:red">选择一个处理死锁代价最小的事务撤销，并释放其持有的锁</span>

13. 从低一级的范式通过模式分解达到高一级范式的过程称为 ____ ____。  
    答案：<span style="color:red">规范化</span>

15. 在数据库设计中合并分 E-R 图时可能遇到的冲突主要有：属性冲突、命名冲突和 ____ ____。

## 二、判断题汇总

### 【2011 图片卷】判断题

1. 概念模型一般是稳定的，只要用户的需求不变，概念模型也不变。  
   答案：<span style="color:red">T</span>

2. 在关系数据库中，元组的各个分量是有序的，但是元组的次序是无关紧要的。  
   答案：<span style="color:red">T</span>

3. 在关系运算中，只要参加运算的关系是有限的，结果关系也一定是有限的。  
   答案：<span style="color:red">T</span>

4. 数据库的合法用户可以操纵数据库中的所有数据。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">合法用户只能操纵被授权（GRANT）范围内的数据，而不是数据库中的所有数据。</span>

5. 关系数据库中的视图只能建立在基表上。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">视图既可以建立在基本表上，也可以建立在其他视图之上，或同时建立在基本表和视图之上。</span>

6. 同一关系内部属性之间不存在参照约束关系。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">同一关系内部属性之间也可以存在参照约束（自参照）。例如员工表中"直接上级编号"参照本表的"员工编号"。</span>

7. 静态转储不影响事务的运行。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">静态转储期间不允许有任何事务运行，因此会影响事务的运行；只有动态转储才不影响事务的运行。</span>

8. 封锁粒度越大，需要的锁越多，系统开销也越大。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">封锁粒度越大，需要的锁越少，系统开销越小，但并发度越低；粒度越小才需要更多的锁，开销也越大。</span>

9. 每个函数依赖集的最小函数依赖集都是唯一的。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">一个函数依赖集的最小函数依赖集（最小覆盖）一般不唯一，可能存在多个互相等价的最小依赖集。</span>

10. 只包含两个属性的关系一定属于 BCNF。  
    答案：<span style="color:red">T</span>

### 【2019】判断题

1. 关系中元组的次序是无关紧要的，但是元组的分量必须是有序的。  
   答案：<span style="color:red">T</span>

2. 在一个表上建立多个聚集索引可以提高关系数据库的访问效率。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">一个表只能建立一个聚集索引（因为聚集索引决定了数据记录的物理存储顺序），不能建立多个。</span>

3. 在数据库设计中，将 ER 图转换成关系数据模型是在概念设计阶段完成的。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">将 E-R 图转换成关系数据模型是在逻辑结构设计阶段完成的；概念设计阶段的任务是设计 E-R 图。</span>

4. 关系模式的规范化程度越高，数据操作效率也一定越高。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">规范化程度越高意味着分解的关系越多，查询时往往需要更多的连接操作，反而可能降低数据操作效率。规范化程度高有利于减少冗余和异常，但与操作效率不是正相关。</span>

5. 数据库的逻辑独立性源于三级模式结构中模式与内模式之间的映像。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">逻辑独立性源于"外模式/模式"映像；"模式/内模式"映像保证的是物理独立性。</span>

6. 在关系 DB 中，任何二元关系模式如果属于 3NF 必定属于 BCNF。  
   答案：<span style="color:red">T</span>

7. 采用增量备份，数据的恢复可以不使用事务日志文件。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">无论采用哪种备份方式，事务日志文件都是数据库恢复必不可少的工具；只有结合日志文件才能将数据库恢复到一致状态。</span>

8. 参照完整性约束不仅存在于关系之间，同一个关系内部属性之间也可以有参照约束关系。  
   答案：<span style="color:red">T</span>

9. 关系模式的规范化是使得关系属性间的数据依赖逐渐趋向合理的过程。  
   答案：<span style="color:red">T</span>

10. Transact-SQL 的表值函数可以替代视图。  
    答案：<span style="color:red">T</span>

### 【2022】判断题

1. 数据库的合法用户可以操纵数据库中的所有数据。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">合法用户只能操纵被授权（GRANT）范围内的数据，而不是数据库中的所有数据。</span>

2. 在强制存取控制中，仅当主体的许可证级别等于客体的密级时，该主体才能读相应的客体。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">在强制存取控制中，仅当主体的许可证级别"不低于（大于等于）"客体的密级时，该主体才能读相应的客体；而写操作要求主体的许可证级别"不高于（小于等于）"客体的密级。</span>

3. 关系数据库中的所有视图可以完全象基本表一样进行查询和更新操作。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">视图都可以查询，但并非所有视图都可以更新。例如包含聚合函数、GROUP BY、DISTINCT、多表连接等的视图通常是不可更新的，只有满足一定条件的"行列子集视图"才可以执行更新操作。</span>

4. 关系模式的规范化程度越高，操作数据的效率就越高。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">规范化程度越高，关系分解越细，查询时往往需要更多的连接操作，反而会降低操作效率。规范化主要是减少数据冗余和异常，并不直接提升操作效率。</span>

5. 关系数据库中的关系必须是有限元组的集合。  
   答案：<span style="color:red">T</span>

6. 关系模式的外键必须与相应的主键同名。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">外键和被参照的主键不要求同名，只要求取自同一域（数据类型、取值范围一致）即可。同名只是常见的命名习惯，并非强制要求。</span>

7. 当用户删除一个表后，建立在该表上的视图仍旧存在，但无法使用了。  
   答案：<span style="color:red">T</span>

8. 每个表都可以拥有多个聚集索引。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">每个表最多只能建立一个聚集索引，因为聚集索引决定了数据记录在物理存储上的排列顺序，而物理顺序只能有一种。非聚集索引则可以建立多个。</span>

9. 在数据库设计中，将 ER 图转换成关系数据模型的过程属于概念设计阶段。  
   答案：<span style="color:red">F</span>  
   正确说法：<span style="color:red">将 E-R 图转换成关系数据模型属于逻辑结构设计阶段；概念设计阶段的任务是建立 E-R 图（概念模型）。</span>

10. 触发器是一种实现复杂完整性约束的特殊存储过程。它的执行是通过 EXECUTE 语句调用。  
    答案：<span style="color:red">F</span>  
    正确说法：<span style="color:red">触发器是由事件（如 INSERT、UPDATE、DELETE）自动驱动执行的，不需要也不能用 EXECUTE 语句显式调用；用 EXECUTE 调用的是普通的存储过程。</span>

## 三、单项选择题汇总

### 【2011 图片卷】选择题

1. 负责数据库系统建立、维护和协调工作的人员是（ ）。  
   A. 最终用户　B. 应用程序员　C. 系统分析员　D. 数据库管理员  
   答案：<span style="color:red">D</span>
   解析：D 正确，数据库管理员（DBA）负责数据库的建立、运行维护、权限与性能协调。A 只是使用系统；B 负责编写应用程序；C 主要做需求分析和系统设计，不负责数据库日常管理。

2. 采用树型结构表示各类实体以及实体间联系的模型是（ ）。  
   A. 关系模型　B. 层次模型　C. 网状模型　D. 对象模型  
   答案：<span style="color:red">B</span>
   解析：B 正确，层次模型用树形结构表示记录及联系。A 用二维表；C 用网状结构，能表示更复杂的多对多联系；D 以对象、类、继承等概念组织数据。

3. 下列选项中，与视图对应的是（ ）。  
   A. 外模式　B. 模式　C. 内模式　D. 索引  
   答案：<span style="color:red">A</span>
   解析：A 正确，视图是用户看到的局部逻辑结构，属于外模式层。B 是全局逻辑结构；C 是物理存储结构；D 是存取路径，不是用户视图。

4. 关系中的列，称为（ ）。  
   A. 元组　B. 域　C. 属性　D. 目或度  
   答案：<span style="color:red">C</span>
   解析：C 正确，关系中的列叫属性。A 是关系中的行；B 是属性的取值范围；D 是关系中属性的个数。

5. 若 R 有 m 个元组，S 有 n 个元组，则 R 和 S 的笛卡尔积有（ ）个元组。  
   A. m　B. n　C. m+n　D. m×n  
   答案：<span style="color:red">D</span>
   解析：D 正确，笛卡尔积会把 R 的每个元组与 S 的每个元组配对，所以元组数为 m×n。A、B 只考虑了单个关系；C 是相加，不符合配对组合。

6. 对两个关系 R 和 S 进行连接操作时，如果希望结果包含 R 和 S 中不满足连接条件的元组，应执行（ ）。  
   A. 内连接　B. 左外连接　C. 右外连接　D. 完全外连接  
   答案：<span style="color:red">D</span>

4. 有关关系数据库的设计，如下说法正确的是（ ）。

5. 数据库的逻辑设计阶段得到的结果是（ ）。

   答案：<span style="color:red">C</span>

6. R(S, D, M)，F ={S→D, D→M}，关系 R 的规范化程度至多达到（ ）。  
   A. 1NF　B. 2NF　C. 3NF　D. BCNF  
   答案：<span style="color:red">B</span>
   解析：B 正确，S 是候选码，且 S→D、D→M 导致非主属性 M 对候选码 S 存在传递依赖，因此不满足 3NF；由于候选码是单属性 S，不存在非主属性对复合码的部分依赖，所以可达 2NF。A 太低；C、D 都要求消除该传递依赖或要求决定因素为超码。

12. 一般来说，以下哪个情况的列不适合建立索引？

    答案：<span style="color:red">D</span>
    解析：D 正确，重复值多的列选择性差，索引过滤效果弱。A 经常查询有利于索引发挥作用；B 索引可辅助排序；C 主键通常自带索引，外键列建索引也常有利于连接和约束检查。

14. 下列聚集函数中不忽略空值 NULL 的是（ ）。

    答案：<span style="color:red">C</span>

15. 下列二元关系运算中去掉重复属性列的是（ ）。  
    A. 笛卡尔积　B. 条件连接　C. 等值连接　D. 自然连接  
    答案：<span style="color:red">D</span>
    解析：D 正确，自然连接会按同名属性等值连接，并在结果中去掉重复的同名属性列。A 只是组合两个关系；B 按条件连接但不自动去重复列；C 虽按等值条件连接，但仍保留两边参与比较的属性列。

16. 表的创建者可以通过（ ）语句把表的某些权限授予其他用户。  
    A. SELECT　B. UPDATE　C. GRANT　D. REVOKE  
    答案：<span style="color:red">C</span>

17. 大型集中式关系数据库，查询优化的重点是使（ ）最小化。

18. 对于小关系上的选择操作应该选用的实现方法是（ ）。

19. 关于自主存取控制 DAC 和强制存取控制 MAC，论述正确的是（ ）。

20. 在分组检索中，要去掉不满足条件的分组和不满足条件的记录，应当（ ）。

### 【2019】简答题

1. 简要解释嵌入式 SQL 中游标的概念和作用。

   答案：<span style="color:red">数据库镜像是 DBMS 自动把整个数据库或关键数据复制到另一个磁盘或存储设备上，并保持镜像与主数据库一致。作用是介质故障时可快速切换和恢复，也可在一定程度上分担读操作；缺点是维护镜像会增加系统开销。</span>

   答案：<span style="color:red">把概念结构转换为一般关系模型；将关系模型转换为特定 DBMS 支持的数据模型；进行规范化和模式优化；设计外模式和应用视图；根据完整性、安全性和应用需求进一步调整关系模式。</span>

### 【2022】简答题

1. E-R 模型向关系数据库转化的主要转换规则是什么？

3. 数据管理经过了哪些主要阶段？  
   答案：<span style="color:red">人工管理阶段、文件系统阶段、数据库系统阶段。</span>

   答案：<span style="color:red">AB 是候选键。因为 (AB)+ 初始为 AB；由 A→D 得 ABD；由 AB→DE 得 ABDE；由 E→H 得 ABDEH，覆盖全部属性。A+={A,D}，B+={B}，均不能覆盖全部属性，所以 AB 最小，是候选键。</span>

JOIN 课程表 C ON SC.课程号 = C.课程号
WHERE C.课程名 = '数据库原理';

-- (3) 查询至少选修了两门课程的学生姓名
SELECT S.姓名
FROM 学生表 S
JOIN 学生选课表 SC ON S.学号 = SC.学号
GROUP BY S.学号, S.姓名
HAVING COUNT(DISTINCT SC.课程号) >= 2; </code> </pre>

### 【2011 图片卷】医院病房管理信息系统设计题

题目要点：一个科室有多个病房和多个医生；一个病房只属于一个科室；一个医生只属于一个科室，但可负责多个病人的诊治并给出诊治意见；每个病房有多张病床；一个病人只能占用一张病床；由于轮流值班，一个病人可能在不同时间由不同医生负责诊治。要求：E-R 图、关系模型、函数依赖和主键、范式判断与 3NF 分解。

答案：

<pre style="color:red"> <code> 1. 概念结构 / E-R 设计
实体：
科室 Department(DeptID, DeptName, Location, Phone)
病房 Ward(WardID, WardNo, DeptID)
病床 Bed(BedID, BedNo, WardID)
医生 Doctor(DoctorID, DoctorName, Title, DeptID)
病人 Patient(PatientID, PatientName, Gender, Age, BedID)
诊治 Treatment(TreatID, DoctorID, PatientID, TreatTime, Opinion)

联系：
Department 1: n Ward
Department 1: n Doctor
Ward 1: n Bed
Bed 1:1 Patient 或 Bed 1: n PatientHistory（若考虑历史占床）
Doctor 与 Patient 通过 Treatment 构成 m: n 联系，联系属性包括 TreatTime、Opinion。

2. 关系模型
Department(DeptID, DeptName, Location, Phone) 主码 DeptID
Ward(WardID, WardNo, DeptID) 主码 WardID，外码 DeptID
Bed(BedID, BedNo, WardID) 主码 BedID，外码 WardID
Doctor(DoctorID, DoctorName, Title, DeptID) 主码 DoctorID，外码 DeptID
Patient(PatientID, PatientName, Gender, Age, BedID) 主码 PatientID，外码 BedID，可对 BedID 加 UNIQUE 表示一个病人占一张床且床不重复占用
Treatment(TreatID, DoctorID, PatientID, TreatTime, Opinion) 主码 TreatID，外码 DoctorID、PatientID

3. 主要函数依赖
DeptID -> DeptName, Location, Phone
WardID -> WardNo, DeptID
BedID -> BedNo, WardID
DoctorID -> DoctorName, Title, DeptID
PatientID -> PatientName, Gender, Age, BedID
TreatID -> DoctorID, PatientID, TreatTime, Opinion

4. 范式判断
上述关系中每个非主属性均直接依赖于各自主码，不存在非主属性对码的部分依赖和传递依赖，通常均满足 3NF。
若把科室名、医生名、病房号等混入 Patient 或 Treatment 大表，会产生传递依赖和冗余，应分解为上述 3NF 关系。</code> </pre>

### 【2019】医院门诊管理系统设计题

题目要点：医院有多个科室，每个科室有多位门诊医生，每位医生只在一个科室出诊；患者可到各科室看病，医生根据病情开具治疗药品；记录患者基本信息、看病情况、诊断意见、药品清单及数量；管理药品基本信息；创建“曾到骨科就诊患者基本信息”的视图及相关建表语句。

答案：

<pre style="color:red"> <code> 1. E-R 设计
实体：
科室 Department(DeptID, DeptName, Location, Phone)
医生 Doctor(DoctorID, DoctorName, Title, DeptID)
患者 Patient(PatientID, PatientName, Gender, Age, Phone)
药品 Medicine(MedID, MedName, Spec, Price)
就诊 Visit(VisitID, PatientID, DoctorID, VisitTime, Diagnosis)
用药明细 VisitMedicine(VisitID, MedID, Quantity)

联系：
Department 1: n Doctor
Patient 与 Doctor 通过 Visit 构成 m: n 联系，Visit 记录时间和诊断意见
Visit 与 Medicine 通过 VisitMedicine 构成 m: n 联系，记录药品数量

2. 关系模式
Department(DeptID, DeptName, Location, Phone) 主码 DeptID
Doctor(DoctorID, DoctorName, Title, DeptID) 主码 DoctorID，外码 DeptID
Patient(PatientID, PatientName, Gender, Age, Phone) 主码 PatientID
Medicine(MedID, MedName, Spec, Price) 主码 MedID
Visit(VisitID, PatientID, DoctorID, VisitTime, Diagnosis) 主码 VisitID，外码 PatientID、DoctorID
VisitMedicine(VisitID, MedID, Quantity) 主码 (VisitID, MedID)，外码 VisitID、MedID

3. 建表和视图示例
CREATE TABLE Department(
    DeptID CHAR(10) PRIMARY KEY,
    DeptName VARCHAR(50) NOT NULL,
    Location VARCHAR(100),
    Phone VARCHAR(30)
);

CREATE TABLE Doctor(
  DoctorID CHAR(10) PRIMARY KEY,
  DoctorName VARCHAR(50) NOT NULL,
  Title VARCHAR(50),
  DeptID CHAR(10),
  FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
);

CREATE TABLE Patient(
  PatientID CHAR(10) PRIMARY KEY,
  PatientName VARCHAR(50) NOT NULL,
  Gender CHAR(2),
  Age INT,
  Phone VARCHAR(30)
);

CREATE TABLE Visit(
  VisitID CHAR(10) PRIMARY KEY,
  PatientID CHAR(10),
  DoctorID CHAR(10),
  VisitTime DATETIME,
  Diagnosis VARCHAR(500),
  FOREIGN KEY (PatientID) REFERENCES Patient(PatientID),
  FOREIGN KEY (DoctorID) REFERENCES Doctor(DoctorID)
);

CREATE VIEW OrthopedicsPatients AS
SELECT DISTINCT P.PatientID, P.PatientName, P.Gender, P.Age, P.Phone
FROM Patient P
JOIN Visit V ON P.PatientID = V.PatientID
JOIN Doctor D ON V.DoctorID = D.DoctorID
JOIN Department Dept ON D.DeptID = Dept.DeptID
WHERE Dept.DeptName = '骨科'; </code> </pre>

### 【2022】图书馆管理数据库系统设计题

题目要点：管理出版社、书籍、每本馆藏副本、读者及可借数量限制；支持到期图书查询、馆藏图书种类最多出版社查询、借阅过某作者所有书籍的读者查询；要求 E-R 图、3NF 关系模型、创建书籍表和读者表、建立北京出版社书籍视图。

答案：

<pre style="color:red"> <code> 1. E-R 设计
实体：
Publisher(PubID, PubName, Address, City)
Book(BookID, Title, Author, PubYear, PubID)
BookCopy(CopyID, BookID, Status, InDate)
Reader(ReaderID, ReaderName, Email, MaxBorrow)
Borrow(BorrowID, ReaderID, CopyID, BorrowDate, DueDate, ReturnDate)

联系：
Publisher 1: n Book
Book 1: n BookCopy
Reader 与 BookCopy 通过 Borrow 构成 m: n 借阅联系，联系属性包括 BorrowDate、DueDate、ReturnDate。

2. 关系模型，符合 3NF
Publisher(PubID, PubName, Address, City) 主码 PubID
Book(BookID, Title, Author, PubYear, PubID) 主码 BookID，外码 PubID -> Publisher(PubID)
BookCopy(CopyID, BookID, Status, InDate) 主码 CopyID，外码 BookID -> Book(BookID)
Reader(ReaderID, ReaderName, Email, MaxBorrow) 主码 ReaderID
Borrow(BorrowID, ReaderID, CopyID, BorrowDate, DueDate, ReturnDate) 主码 BorrowID，外码 ReaderID、CopyID

各表中非主属性均直接依赖于各自主码，不存在非主属性对码的部分依赖和传递依赖，符合 3NF。

3. 创建书籍表、读者表
CREATE TABLE Book (
    BookID CHAR(20) PRIMARY KEY,
    Title VARCHAR(200) NOT NULL,
    Author VARCHAR(100),
    PubYear INT,
    PubID CHAR(10),
    FOREIGN KEY (PubID) REFERENCES Publisher(PubID)
);

CREATE TABLE Reader (
  ReaderID CHAR(20) PRIMARY KEY,
  ReaderName VARCHAR(80) NOT NULL,
  Email VARCHAR(120),
  MaxBorrow INT NOT NULL CHECK (MaxBorrow >= 0)
);

4. 建立出版社在北京的所有书籍视图
CREATE VIEW BeijingPublisherBooks AS
SELECT B.BookID, B.Title, B.Author, B.PubYear,
       P.PubName, P.Address, P.City
FROM Book B
JOIN Publisher P ON B.PubID = P.PubID
WHERE P.City = '北京'; </code> </pre>
